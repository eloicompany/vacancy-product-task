# Тестове завдання — продукт з нуля разом з AI

Привіт! Це завдання однакове для всіх рівнів, від Trainee до Senior. Ви обираєте тему й **самостійно, разом з AI-інструментами, будуєте робочий продукт від ідеї до запуску локально**.

Нас цікавить не кількість коду, а те, як ви мислите:

- **як продуктолог:** для кого продукт і як він заробляє;
- **як архітектор:** як система побудована і чому саме так;
- **як інженер:** наскільки продукт безпечний, швидкий і охайний.

Рівень впливає лише на те, наскільки глибоко ми чекаємо опрацювання (див. [Очікування за рівнем](#очікування-за-рівнем)).

> 🕐 **Строк** вам повідомить рекрутер. Краще менше функцій, але доведених до кінця, ніж багато напівготових.

---

## Крок 1 — оберіть тему

Оберіть **одну** тему. Для кожної вказано:

- **Ядро** — мінімум, який має працювати у всіх.
- **Гроші** — звідки продукт бере дохід. Модель можна змінити, якщо обґрунтуєте.
- **Глибше** — напрямки для Middle і Senior. Вибирайте з них або пропонуйте свої.

### 1. Онлайн-запис для малого бізнесу
Салони, репетитори, СТО: клієнт сам записується на вільний час.
- **Ядро:** послуги й розклад майстрів, вільні слоти, запис клієнта без дублів на той самий час, кабінет бізнесу зі списком записів.
- **Гроші:** підписка для бізнесу (тарифи з лімітами майстрів чи записів), передоплата за запис.
- **Глибше:** нагадування (email/Telegram), часові пояси, скасування й no-show, кілька філій, онлайн-передоплата з вебхуком.

### 2. Рахунки й оплати для фрилансерів
Фрилансер виставляє рахунок, клієнт оплачує за посиланням.
- **Ядро:** клієнти, створення рахунку з позиціями, публічна сторінка рахунку, статуси (чернетка → виставлено → оплачено), PDF.
- **Гроші:** freemium (N рахунків на місяць безкоштовно), комісія з оплати, платний брендинг.
- **Глибше:** тестова оплата з вебхуком та ідемпотентністю, валюти, повторювані рахунки, нагадування про прострочені, звіт для податкової.

### 3. Продаж цифрових продуктів
Автор продає курси, шаблони, електронні книжки. Покупець отримує доступ після оплати.
- **Ядро:** вітрина автора, сторінка продукту, кошик чи покупка в один клік, доступ до контенту лише після оплати, кабінет покупця.
- **Гроші:** комісія платформи з продажу, підписка автора на розширені можливості.
- **Глибше:** промокоди, захищені посилання на файли з терміном дії, партнерська програма, повернення коштів, аналітика продажів.

### 4. Служба підтримки (helpdesk) для SaaS
Компанія приймає звернення клієнтів і відповідає на них командою.
- **Ядро:** створення звернення (форма чи email), черга звернень, призначення агенту, статуси, переписка, база знань.
- **Гроші:** оплата за місце агента, платні функції (SLA, AI-підказки).
- **Глибше:** кілька компаній в одній системі (multi-tenant), SLA з ескалацією, AI-чернетки відповідей, пошук, віджет на сайт.

### 5. Своя тема
Можна запропонувати свою тему. Вона має бути продуктом, за який хтось платитиме, і мати складність, не меншу за теми вище. **Погодьте її з рекрутером до старту.**

## Крок 2 — побудуйте продукт

**Стек обираєте самі.** Ми працюємо переважно з TypeScript, Next.js і PostgreSQL, але оцінюємо обґрунтованість вибору, а не збіг зі стеком компанії.

**AI-інструменти обов'язкові:** Claude Code, Cursor, Copilot, Codex чи будь-які інші. Ми хочемо побачити, як ви керуєте AI:

- ставите задачі;
- перевіряєте результат;
- не пропускаєте помилок.

Ви відповідаєте за кожен рядок у репозиторії. На дзвінку питатимемо, чому код написано саме так.

Що має бути в продукті:

| Напрям | Що ми хочемо побачити |
|---|---|
| **Продукт** | Зрозуміло, для кого продукт і яку проблему він вирішує. Користувач проходить основний сценарій без підказок. Монетизація **реалізована в коді**: тарифи, ліміти, paywall, оплата в тестовому режимі (Stripe test mode, sandbox LiqPay чи WayForPay) або чесна заглушка. |
| **Архітектура** | Чіткий поділ на шари й модулі, продумана модель даних, бізнес-логіка не розмазана по UI. Рішення обґрунтовані. |
| **Клієнтська частина** | Зручний UX, стани завантаження, порожнечі й помилки, адаптивність під телефон, базова доступність (клавіатура, контраст, підписи полів). |
| **Безпека** | Автентифікація. Перевірка прав **на сервері**: користувач не бачить чужих даних. Валідація входу. Секрети не потрапляють у репозиторій (є `.env.example`). Захист від типових атак (OWASP Top 10). |
| **Продуктивність** | Індекси під реальні запити, пагінація, відсутність N+1, розумний розмір бандла, кешування там, де воно доречне. |
| **Перевикористання** | Спільні компоненти й модулі замість копіпасти. Готові бібліотеки там, де писати своє немає сенсу, і пояснення, чому обрано саме їх. |
| **Якість** | Тести на критичну логіку (гроші, доступи, бронювання), лінтер, форматування, CI у GitHub Actions. Запуск однією-двома командами (`docker compose up` тощо), тестові дані й демо-акаунти. |

## Очікування за рівнем

Нижче — мінімум. Усе, що понад нього, — плюс.

| Рівень | Мінімум |
|---|---|
| **Trainee** | Ядро теми працює. Вхід користувача. Сторінка тарифів із лімітом безкоштовного плану. Зрозумілий README із запуском. |
| **Junior** | + валідація й обробка помилок, права доступу на сервері, тести на основну логіку, адаптивний UI, `docker compose` для запуску. |
| **Middle** | + кілька ролей, тестова оплата з вебхуком (перевірка підпису, ідемпотентність), CI, пагінація й індекси, схема архітектури та модель даних у README. Мінімум один пункт із «Глибше». |
| **Senior** | + щонайменше два пункти з «Глибше». Фонові задачі чи черга, логування й метрики, модель загроз, продуктова аналітика (воронка до оплати). Описані компроміси: що буде на 100× навантаженні і що ви свідомо не робили. |

## Крок 3 — здайте роботу

1. Публічний репозиторій **у вашому акаунті** GitHub з повною історією комітів. Не стискайте історію в один коміт: нам цікаво, як рухалася робота.
2. **README** вашого проєкту:
   - **Продукт:** для кого, яку проблему вирішує, як заробляє, чому саме так.
   - **Запуск:** команди, демо-акаунти, як перевірити оплату.
   - **Архітектура:** схема, модель даних, ключові рішення та їхні альтернативи.
   - **Стек:** мова, фреймворки, бібліотеки, сервіси, сторонні репозиторії і шаблони. Чесно вкажіть усе, що взяли готовим.
   - **Безпека й продуктивність:** що зроблено і як це перевірити.
   - **Робота з AI:**
     - які інструменти використовували й навіщо;
     - ваші правила й інструкції для агента (`CLAUDE.md`, `AGENTS.md`, `.cursor/rules` — покладіть у репозиторій);
     - 2–3 приклади, де AI помилився і як ви це виявили.
   - **Що далі:** що не встигли і що зробили б наступним.
3. **Відео до 5 хвилин** з демо основного сценарію: від реєстрації до оплати.
4. Посилання на репозиторій і відео надішліть рекрутеру.

**Правила:**

- Реальні секрети, персональні дані й бойові платіжні ключі не використовуйте — лише тестові.
- Готові бойлерплейти й стартові шаблони дозволені, але їх треба назвати в README. Видавати чужу роботу за свою — підстава для відмови.
